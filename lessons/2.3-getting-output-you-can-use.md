## Read
Writing for a person is forgiving. Writing for a program is not. If output goes into a spreadsheet, a database or the next step of a workflow, the format must be exact.

Tips:
- **Name every field** and its type: `"amount": number`.
- **Say what to do when information is missing** ("use null"). Otherwise the model may guess.
- **Forbid extras**: "Return only the JSON, no explanation."
- **Show one example** of valid output.

Some tools can enforce a format for you. When they can't, you check it yourself with a small script. Never assume the format held.

## Example
Pull fields from: "Invoice 3321 from Harbor Supply, due March 4, total $1,250.00."
Output: `{"invoice":"3321","vendor":"Harbor Supply","due":"2026-03-04","total":1250.00}`

## Puzzle: Extract clean JSON
Write a prompt that makes the simulated model turn 5 messy messages into valid JSON with required fields. One message is missing a field, one has two amounts, one uses a different date style.

- Goal: all 5 outputs parse as JSON and 4 of 5 are correct.
- Hidden tests: the 5 messages.
- Grader: a script that parses the JSON and compares fields.

## Hints
1. What should happen when the date is missing?
2. How should the date be written?

## Reflect
What step would break if one output was almost-JSON?
