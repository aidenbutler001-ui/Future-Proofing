## Read
Lesson 2.6 tested a prompt. A system with tools and memory needs the same discipline across whole tasks. An **eval** is a set of tasks with a way to score the result. Rerun it when you change the prompt, the tools, the harness or the model.

What to score:
- **Outcome:** did it reach the right result?
- **Process:** did it use sensible steps and stay within limits?
- **Safety:** did it avoid forbidden actions?
- **Cost and time:** tokens used, steps taken.

Because outputs vary run to run, run each task several times and look at the rate, not one result. Keep a record, and watch for **regressions**: things that used to pass and now fail, especially after a model update.

**Cost note.** Evals cost tokens too, and each task is run several times. Keep the test set small and well chosen, record cost per task alongside pass rate, and watch for changes that pass more tests but cost much more (lesson 6.5).

**Opsec check.** Test sets often contain real examples. Use fake or redacted data in evals, and include attacks that try to extract confidential content.

## Puzzle: Find the regression
You get results from two versions of an agent on 20 tasks, run 3 times each. One change improved most tasks and broke some.
- Goal: name the tasks that regressed, and say whether the overall change is worth keeping.
- Hidden tests: the 20 tasks' results, including one task that looks worse only because of random variation.
- Grader: answer key; feedback explains the difference between a real regression and noise.

## Hints

2. What counts as a meaningful drop for a task run only 3 times?
