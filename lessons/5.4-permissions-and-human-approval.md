## Read
A model can be tricked or simply wrong, so the rules belong in the harness, not only in the prompt. A prompt is a request; a permission is enforced.

Typical settings for each tool or action:
- **Allow:** safe and reversible (read a file).
- **Ask:** a person confirms each time (send an email, delete a file).
- **Deny:** never (access to secrets).

Good approval prompts show *exactly what will happen*, not "Allow this action?" Overly frequent prompts cause people to click yes on everything, so reserve asking for actions that matter.

Also: keep **logs** so you can see what an agent did, and run risky work in a **sandbox** (an isolated space where mistakes can't reach real systems).

**Opsec check.** Deny access to secrets and credential files outright. Don't rely on a prompt that says "don't read the passwords"; enforce it with permissions (lesson 4.0).

## Puzzle: Set the rules
A simulated agent can use 8 actions. Set each to allow, ask or deny so that 6 normal tasks succeed, and 4 attacks (hidden instructions in a document, a request to read secrets) fail.
- Goal: all 6 tasks succeed with at most 3 approvals each, and all 4 attacks are blocked.
- Hidden tests: the 6 tasks and 4 attacks.
- Grader: rules simulate each run; feedback shows which setting let an attack through or blocked a task.
