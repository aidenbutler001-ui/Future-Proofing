## Read
When a document assistant gives a bad answer, check in order:
1. **Was the right chunk retrieved?** If not, the model never saw the answer. Fix chunking, wording or search.
2. **Was the chunk out of date or wrong?** The system faithfully repeats whatever it finds. Old policies produce old answers.
3. **Did chunks conflict?** The model may pick one or blend them.
4. **Did the model misread the right chunk?** Rarer, but possible. Ask for the quote.
5. **Was there a hidden instruction?** Text in a document or web page can say "ignore your previous instructions and..." (**prompt injection**). The model may treat it as a command. Defenses: label documents as data in the system prompt, give the model no powers it doesn't need, and never let document text approve actions.

Track failures by cause. The fix for each is different.

**Opsec check.** Stale or mixed-up collections can leak documents to the wrong audience. Label each document's sensitivity, keep collections separate by audience, and test with a question that someone without access might ask.

## Puzzle: Diagnose the bad answers
You get 8 failed answers from a document assistant with the question, retrieved chunks and answer. Label the cause of each, then fix the instruction or the settings for the two that you can fix there.
- Goal: 7 of 8 causes labeled correctly and both fixes work on a rerun.
- Hidden tests: the 8 cases, including one injection and one out-of-date source.
- Grader: answer key plus a rerun simulation for the two fixes.

## Hints
1. Look at what was retrieved before blaming the model.
2. Which text in the chunk was written by the document's author, not you?

## Module 3 wrap-up
Pick a small collection of documents you care about (class notes, a handbook). Build an assistant instruction that answers from them with citations, and write 8 test questions, including 2 it should decline. Report which cases failed first and which of the five causes explained them.
