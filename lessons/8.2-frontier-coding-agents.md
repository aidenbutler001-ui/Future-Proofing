## Read
A **coding agent** works inside a software project. It reads files, proposes edits, runs commands and tests, reads the results, and tries again. Everything from this course appears in one place:

| Course idea | In a coding agent |
|---|---|
| Model + harness (5.1) | The model plus the program that lets it touch your files |
| Tools (4.1) | Read file, edit file, run command, search code |
| Memory (5.2) | Project notes the agent reads at the start of each session |
| Permissions (5.4) | Which commands run freely, which ask first, which are blocked |
| Evals (5.5) | The project's tests, which tell the agent whether it is done |

**Why code is the best case for agents:** there is a built-in check. Tests pass or fail, programs run or crash. The agent gets fast, objective feedback, which is rare in other fields.

**Habits that keep you in control (also useful when you can't code well):**
1. **Describe the goal and the "done" test** before the agent starts. "The export button downloads a CSV with these columns" beats "improve exports".
2. **Keep work in version control** so every change can be undone and compared.
3. **Read the changes before you accept them,** or have the agent explain each one. Code you don't understand is a risk you own.
4. **Run it in a sandbox** or a copy when it can delete or send things.
5. **Distrust generated security-sensitive code** (logins, payments, handling other people's data) and get it reviewed.
6. **Watch the scope.** Agents sometimes change more than you asked.
7. **Never paste secrets** into the project or the prompt (lesson 7.1).

**Where it leads:** people with little programming background can now build useful personal tools and automations. The skill that matters is describing what you want precisely and checking that you got it, which is what the rest of this course teaches.

## Example
Request: "Add a dark mode toggle." A good run: the agent reads the style files, makes a small change, runs the existing tests, and shows a short summary and the changed files. A poor run: it rewrites the whole stylesheet and removes a feature that had no test.

**Opsec check.** A coding agent runs commands with your account. Work in a copy or container, keep secrets out of the project, check that nothing sensitive is committed to version control, and keep approvals on (lesson 4.0).

## Puzzle: Direct the agent
A simulated coding agent works on a small project with 5 tests (2 failing) and a feature request. You write the instructions and approve or reject each change it proposes.
- Goal: all tests pass, the feature works, and nothing outside the task changed.
- Hidden tests: 3 extra checks, including one that catches a change the agent makes without being asked.
- Grader: rules compare the final project to the expected state; feedback shows the change you should have rejected.

## Hints
1. What is your definition of done?
2. Which proposed change is bigger than the task?
