## Read
This module gives models *tools*: reading files, running commands, browsing, sending messages. On a computer that also holds confidential documents, credentials and logged-in accounts, that is the highest-risk place to run an agent. The agent acts with **your** permissions. If it is wrong, tricked (lesson 7.2), or simply careless, it can read, change, delete or send anything you can.

**The rule: least privilege, by default.** Give the agent only what the single task needs.

**What an agent could reach on an ordinary computer:**
- Documents, downloads, desktop and synced cloud folders
- Saved passwords, browser sessions and cookies (logged-in email, bank, work accounts)
- SSH keys, API keys, cloud credentials, configuration files
- Other people's data you are responsible for
- The screen, clipboard, notifications and open windows
- The network: it can send data out

**Practical setup, from strongest to weakest:**
1. **Separate environment.** Use a virtual machine, a container, or a dedicated computer with no confidential material on it. Best choice for anything touching sensitive work.
2. **Separate user account or browser profile** with nothing logged in except what the task needs.
3. **A scoped folder.** Give the agent one working folder, preferably a *copy* of the files, read-only when it only needs to read. Never point it at your home folder, entire drive, or a sync folder holding other projects.
4. **Block the secrets.** Keep keys, password managers and credential files out of reach. Don't store secrets in files an agent can read.
5. **Limit the network.** If it doesn't need the internet, turn it off. If it does, restrict where it can send data (lesson 7.2: private data, untrusted input and a way out should never all be present).
6. **Keep approvals on.** Don't use "auto-approve everything" modes outside an isolated environment. Read each command and action before allowing it, especially deleting, sending, uploading, installing and anything that changes settings.
7. **Back up first,** and keep the originals somewhere the agent can't write.
8. **Log and review** what it did.

**For agents that watch your screen (lesson 8.3):** everything visible is input. Close confidential documents, email and chat, and silence notifications before starting. Use a separate desktop or account.

**Other habits:**
- **Lock your screen and encrypt your disk,** so a lost laptop doesn't become a breach.
- **Treat downloaded files, web pages and tools as untrusted.** They can carry hidden instructions or malware.
- **Add only tools you trust,** and review the access each one requests (lesson 8.4). Extensions and plugins can read a lot.
- **Don't run an agent on a work machine in ways your employer hasn't approved.** Ask your IT or security team.
- **If you think data went where it shouldn't, report it right away.** Early reports limit the damage; hiding it makes it worse.

## Example
A consultant's laptop holds client contracts. She wants an agent to tidy a folder of her own notes. She copies the notes to a new folder, runs the agent in a container that can see only that copy, with no internet, and with approvals on. The client contracts, her email and her saved passwords are not reachable at all.

## Puzzle: Lock down the workstation
A simulated computer has 12 resources (client contracts folder, notes folder, password manager, SSH keys, logged-in email, a cloud-synced folder, the network...). You get 3 tasks for an agent. For each task, choose the environment and decide which resources to expose and how (none, read-only, read-write, ask first).
- Goal: all 3 tasks finish, and no confidential resource is exposed that the task doesn't need.
- Hidden tests: each task also gets a simulated attack (a file with hidden instructions, a web page asking for credentials) that tries to reach a resource you left open.
- Grader: simulator; feedback names the exposed resource and the path the attack used.

## Hints
1. What is the smallest set of files this task needs?
2. What could an attacker send out if the agent could reach this?
