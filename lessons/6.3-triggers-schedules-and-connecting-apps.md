## Read
A workflow you run by hand is a helper. A workflow that starts by itself is automation. Three ways to start one:

- **Event trigger:** a new email arrives, a form is submitted, a file lands in a folder, a ticket is opened.
- **Schedule:** every weekday at 8:00, first of the month.
- **Manual or request:** a person presses a button or sends a message.

After the trigger, steps use **connectors** to read and write other apps: email, calendars, spreadsheets, databases, chat. Each connector needs **credentials** (keys or logins). Treat those as secrets: never put them in prompts, share the least access needed (lesson 4.2), and rotate them.

You can build automation with no-code platforms, with scripts, or with an agent harness that has tool access. They all share the same parts: trigger, steps, connectors, rules.

Be careful with **loops of your own making.** An automation that replies to emails can trigger itself if it reads its own replies. Add a guard such as "ignore messages sent by me".

**Opsec check.** Credentials are the keys to your accounts. Store them in the platform's secret storage, scope each one narrowly, and rotate them. Don't connect an automation to a whole mailbox, drive or customer database when one label, folder or table will do.

## Puzzle: Wire up the weekly report
A simulator has a calendar, a task tracker, a chat tool and an email tool. Set a trigger and steps to send a Monday summary of last week's finished tasks and this week's meetings to a team channel.
- Goal: the correct summary posts once, on Monday morning, for 3 simulated weeks.
- Hidden tests: a week with no finished tasks, a week with a holiday, and an email that would loop if the trigger is set wrongly.
- Grader: simulator checks timing, content and that no loop occurs.

## Hints
