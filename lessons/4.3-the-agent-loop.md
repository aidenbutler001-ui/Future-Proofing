## Read
A single tool call answers a question. Many tasks need several steps. An **agent** repeats a loop:

1. **Plan:** decide the next step toward the goal.
2. **Act:** call a tool.
3. **Observe:** read the result.
4. **Decide:** is the goal met? If yes, answer. If not, go to 1 with what was learned.

Each pass adds to the context (lesson 1.5), so the agent "remembers" its own steps by rereading them.

What makes it work:
- A **clear goal** and a clear definition of done.
- **Tools that return useful results**, including useful errors ("file not found: try list_files").
- **Checking its own work** against the goal before stopping.

An agent is more flexible than a fixed script because it chooses its steps. That is also why it is less predictable.

## Example
Goal: "Find the cheapest of these three laptops and tell me why." Plan: look up each price. Act: `get_price` three times. Observe: 899, 749, 1,049. Decide: goal met, answer.

**Cost note.** Each loop pass re-sends the growing history, so cost rises faster than the number of steps. Set a step limit and a spend limit, and keep tool results short (lesson 6.5).

**Opsec check.** An agent's notes and step history can contain sensitive data from every tool result. Treat the log as sensitive, and don't share traces without redacting them.

## Puzzle: Run the loop
A simulated agent has two tools (`search_notes`, `calculate`) and a goal: "How many days until the project deadline, based on my notes?" You write the goal text and the tool descriptions, then watch each plan, act and observe step.
- Goal: the agent finishes in at most 4 steps with the correct number.
- Hidden tests: two note sets, one where the deadline is written as "end of next month".
- Grader: rules check the final answer and step count; trace shown with the step where it went wrong.
