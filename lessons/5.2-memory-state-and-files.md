## Read
Models have no memory between calls (lesson 1.5). Any memory is built by the harness:

- **Conversation history:** earlier messages re-sent each turn. Long histories are summarized or trimmed to fit.
- **Notes and files:** the agent writes important facts to a file and reads them later. Works across sessions.
- **Retrieval:** documents are stored in a searchable index; the harness fetches the relevant pieces and places them in context.
- **User profile / preferences:** short saved facts inserted into the system prompt.

Design questions: What gets saved? What gets forgotten? Who can see or edit it? Stored memory can be wrong, outdated or private, so it needs the same care as any data.

**Cost note.** Everything you store and reload is paid for again as input tokens on each run. Keep notes short, summarize old history, and load only what the task needs (lesson 6.5).

**Opsec check.** Memory is stored data. Decide what must never be saved (secrets, personal details, confidential content), who can read the memory, how long it lives, and how to delete it. A note saved today can be sent to a model in the future.

## Puzzle: Give the agent a memory
An agent helps plan a week of meals over 3 sessions. You write the rule for what it saves to a notes file and what it loads at the start of each session.
- Goal: in sessions 2 and 3 the agent respects the allergy and the budget from session 1, and doesn't repeat meals.
- Hidden tests: three simulated sessions, including one that changes a preference.
- Grader: rules check the notes file contents and the final plan; flags notes that grow without limit.
