## Read
In lesson 4.1 the model asked for a tool but did not run it. Something else did. That something is the **harness**: the program around the model. Its jobs:

1. **Build the context:** system prompt, conversation, files, tool list.
2. **Call the model** and read its reply.
3. **Run tool requests**, return results, and handle errors.
4. **Keep state:** history, notes, files (lesson 5.2).
5. **Enforce rules:** permissions, step limits, approvals (lesson 5.4).
6. **Decide when to stop** and show output to the person.

The model supplies judgment. The harness supplies everything else. The same model in a different harness behaves very differently, which is why two products on the same model can feel unlike each other.

A minimal harness is short: a loop that calls the model, runs any tool requested, appends the result, and repeats until the model gives a final answer.

**Opsec check.** The harness decides what the model sees and can do. Review what it sends to the provider and where it stores history. Run it with a limited account (lesson 4.0).

You get a diagram of a working agent product with unlabeled boxes and arrows, plus a list of 10 behaviors ("remembers last week's chat", "asks before deleting", "retries when the tool fails"). Drag each behavior to the part of the harness responsible (context, tools, state, rules, stop).
- Goal: 8 of 10 placed correctly.
- Hidden tests: the 10 behaviors; two could belong to either the model or the harness (the explanation says which and why).
